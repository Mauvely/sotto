# 455480b — Cutting the reassurance chatter from the chrome

Timur's instruction: cut Sotto's unneeded chatter — the LOCAL badge, the
over-use of "local only" / "fully local", and the big compiler-generated
paragraph at the bottom of Settings. That reasoning is for the product page
and the docs, not the product itself.

## Removals

- **`qml/LocalBadge.qml`** — deleted, along with both places it appeared
  (`qml/STitleBar.qml`'s title bar, `qml/Overlay.qml`'s HUD pill) and its entry
  in `CMakeLists.txt`'s `QML_FILES`.
- **The GPU-backend-reason paragraph** — `App.gpuBackendReason` is no longer
  printed anywhere in `qml/SettingsWindow.qml`. The reasoning it carried
  (why a build stayed on `cpu`, what it takes to get a GPU build) moved to
  `README.md`'s Windows section, which is where a reader who wants it will
  look; `App::gpuBackendReason()` and `SOTTO_GPU_REASON` themselves are
  unchanged — they are useful in a log line, not on a page.
- **`src/main.cpp`**'s `--help` banner no longer says "fully local", and drops
  the trailing "All speech recognition runs on this machine. Nothing is sent
  anywhere." sentence.
- **`src/ui/TrayIcon.cpp`**'s disabled "100% local — nothing leaves this
  device" menu item and its surrounding separator are gone — found by the
  grep sweep, not on the original list, but the same reminder-badge pattern
  as the deleted `LocalBadge`.
- **`README.md`**'s intro paragraph no longer restates the local-only claim;
  the Privacy section (unchanged) is now the only place it is made.

## Changes

- **`qml/SettingsWindow.qml`**: the title-bar subtitle now names the job
  ("Voice dictation for any app.") instead of repeating the local-only
  promise. The Speech model section's explanatory paragraph is now a single
  "Backend: %1" line — the section is already titled "Speech model". The
  voice-commands help and the translucency help are each one sentence now
  (the Hyprland `layerrule` fact survives, folded into one clause).
- **`src/core/Settings.cpp`**: the Linux `.desktop` entry's `Comment=` is now
  "Voice dictation".
- **`src/ui/TrayIcon.cpp`**: the tray tooltip is "Sotto — voice dictation"
  (was "Sotto — local dictation"), for consistency with the rest.
- **`src/core/App.cpp`**: `App::initialize()` now logs the backend and the
  reason once at startup with `qInfo()`, since the reasoning that used to live
  in the settings page is exactly what a debugging session wants in a log.
  A stale comment in `statusText()` that budgeted the HUD's width against
  "the LOCAL badge" was corrected now that the badge is gone.

## Bug fixes

- **`qml/Overlay.qml`**'s status text was anchored to the now-deleted badge
  (`anchors.right: badge.left`); it now anchors to the pill's own right edge,
  which also means the status line gets the width the badge used to occupy.

## What was run

`cmake --build build --config Release --parallel 12` (Qt 6.9.0 msvc2022_64,
`-DSOTTO_GPU=cpu`, Visual Studio 17 2022) — clean build. `ctest --test-dir
build -C Release` — 2/2 (`formatter`, `speechgate`). The offscreen harness
rendered both `SOTTO_VIEW=settings` (at `760x2200`) and `SOTTO_VIEW=overlay`;
both screenshots were inspected and show no badge, no leftover paragraph, and
no overlapping chrome. Grepped `qml/` and `src/` for "local only", "fully
local", "100% local", "never leaves", "nothing is sent", "on this machine"
case-insensitively: zero hits outside log lines and code comments.
