# 01f1863 — A repository with no release credentials is not a failed build

## Bug fixes

### Five repositories failed their release on every single push

play, relay, snap, sotto and suite hold none of the four release secrets, and
none of them has ever published a version. So the gate — which asks the feed
what exists for `project(VERSION)` and answers per platform — correctly said
"release this", and the very next step failed on credentials that were never
there:

```
::error::Release configuration incomplete: R2_ACCOUNT_ID R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY MAUVELY_RELEASES_TOKEN.
```

Every merge, in five repositories, as an email. Nothing about it was news
after the first time.

A repository with **none** of the four has not been misconfigured; it has not
been set up, which is a state rather than a mistake, and the honest form of
saying so is a notice and a summary block naming the four secrets — once, where
somebody looking at the run will see it. The gate's later steps are skipped, no
lane runs, and the workflow is green because nothing was wrong.

**Some-but-not-all is still an error.** That one is a mistake — a secret typed
into the wrong repository, or a rotation that missed one — and the completeness
check that already existed still fails loudly on it. The new step only removes
the case where there is nothing to be incomplete about.

## Changes

- `release.yml` gains the `paths-ignore` that `ci.yml` has had since it was
  written: `docs/**`, `changes/**`, `**/*.md`. The version a release is cut
  from lives in `CMakeLists.txt`, so a commit touching only prose cannot start
  one — and this repository's own convention is that every real commit is
  followed by exactly such a commit. Each of those was starting a gate job in
  every repository, for a version it had already decided about a minute earlier.

## What was run

The new step's shell was extracted from the workflow and executed in all three
states: no credentials (`publishable=false`, exit 0, the notice and the summary
table), all four (`publishable=true`), and one of four (`publishable=true`, so
it reaches the completeness check that fails). The eight workflows parse.
