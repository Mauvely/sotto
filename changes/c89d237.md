# c89d237 — Seven runners on one box share one dpkg lock

## Bug Fixes

- **The Linux lane died at "Install Linux GUI dependencies" whenever more than
  one repository built at once.**

  ```
  E: Could not get lock /var/lib/dpkg/lock-frontend. It is held by process 17519 (apt-get)
  ```

  The self-hosted runners are seven services on one Debian box, not seven
  machines. Pushing all eight repositories together started seven jobs within
  the same second, all of which ran `apt-get`, and there is one dpkg lock
  between them.

## Changes

- Every `apt-get` in `ci.yml` and `release.yml` now carries
  `-o DPkg::Lock::Timeout=600`, apt's own mechanism for waiting on the lock
  rather than failing immediately. Requires apt 2.0+; the runner has 3.0.3.
- Nothing was restructured, and the option is inert on a hosted runner where no
  other job shares the machine.

## Additions

- Nothing added.

## Removals

- Nothing removed.

## Verification

All 17 workflows across the eight repositories re-parse as valid YAML, and every
`run:` block containing `apt-get` passes `bash -n`. The `runner.environment ==
'github-hosted'` guard on `release.yml`'s disk-reclaim step is untouched.
